# Development

How to run Polaris on a developer's machine for coding on the platform
itself.  For a shared demo / staging instance, see
[STAGING.md](./STAGING.md).

---

## 1. Host prerequisites

| Tool | Why | Minimum |
|---|---|---|
| Linux or macOS | Dev host | Ubuntu 22.04+ / macOS 13+ |
| Docker Engine / Desktop | Everything runs in containers (api / worker / web included) | 24.x+ with compose v2 |
| `uv` | Resolves the inline-deps PEP 723 metadata in `scripts/*.py` and the root uv workspace | 0.11+ |
| Codex CLI + `codex login` | Workspace containers bind-mount `~/.codex/auth.json` | latest |
| A real domain on Cloudflare DNS | TLS via ACME DNS-01 (Traefik handles certs) | — |

No system Python venv, no system pnpm, no Make.  `./scripts/up.py dev`
preflights Docker + the `.env.dev` file and runs the wizard the first
time it sees a missing required field.

**Host ports bound by `compose.dev.yaml`:**

| Port | Bound on | What |
|---|---|---|
| 80 / 443 / 8090 | `0.0.0.0` | Traefik (HTTP, HTTPS, dashboard).  8090 is unauthenticated — keep loopback-only on shared boxes. |
| 5000 | `127.0.0.1` | Local Docker registry |
| 5432 | `127.0.0.1` (dynamic host port) | Postgres — for `psql` from the host.  `docker compose -f compose.dev.yaml port postgres 5432` shows the assigned port. |

api / worker / web / dev-vnc / minio do **not** bind host ports — they
sit on the `polaris-shared` and `traefik-public` docker networks and
are reached through Traefik on `${POLARIS_DOMAIN}` (e.g.
`https://polaris-dev.xyz/`, `https://vnc.polaris-dev.xyz/`).

## 2. First-time setup

```bash
git clone <repo> && cd polaris-2
cp .env.example .env.dev   # template — `up.py` will fill the rest
./scripts/up.py dev        # interactive wizard on first run
```

(Omitting the `dev` positional triggers an interactive prompt.  Stage
mode follows the same pattern with `cp .env.example .env.stage` +
`./scripts/up.py stage`.)

The wizard prompts for every required field, validates live tokens
(Cloudflare DNS-01, OpenAI, Pinterest), auto-generates `SESSION_SECRET`
when blank, then runs `docker compose -f compose.dev.yaml up -d
--build`.  Field metadata lives in `scripts/lib/spec.py` — single
source of truth for the wizard, README, and CI's non-interactive checks.

Minimum-viable `.env.dev` for local dev:

```
POLARIS_DOMAIN=polaris-dev.xyz             # any domain you control on CF DNS
SESSION_SECRET=<openssl rand -hex 48>      # auto-generated by the wizard if blank
POLARIS_INVITE_CODE=dev-invite             # any string — required for new-user sign-up
POLARIS_DEV_USER_EMAIL=dev@polaris.local   # enables the "Dev Login" button + /auth/dev-login (leave empty to disable)
POLARIS_DEV_USER_NAME=Polaris Dev          # display name for the auto-provisioned dev user
OPENAI_SECRET=                             # leave empty to skip the discovery agent locally
POSTMARK_SERVER_TOKEN=                     # empty → verification codes log to the api container's stdout
```

When Postmark and OpenAI are both empty:

- Sign-in still works via **Dev Login** (bypasses email verification).
- Discovery-agent–routed messages (first message of a new project, or
  any "re-discover") fail at the compiler step.  Skip discovery in
  local work by sending your second+ message via a regular chat turn —
  it goes straight to Codex.
- Everything else — per-workspace compose, IDE, chromium VNC, Codex
  sessions, publish pipeline — works without these keys.

### Building the workspace runtime images

`./scripts/up.py dev` brings up the dev stack itself, but the
**workspace runtime images** that per-session containers spawn from
need `./scripts/build.py`:

```bash
./scripts/build.py                # builds polaris/{ide,workspace,chromium-vnc}:latest
./scripts/build.py --only workspace
./scripts/build.py --force        # ignore mtime cache and rebuild every image
```

Each image carries a `polaris.built-at` LABEL with the mtime of its
Dockerfile + key context files.  Re-runs skip images whose context
hasn't changed.  First `polaris/ide` build takes 5–10 min (yarn
workspaces + `theia generate` + webpack); subsequent builds are
seconds.

### Database migrations

Migrations are not auto-run on api start.  After `./scripts/up.py dev`
brings the stack up:

```bash
docker compose -f compose.dev.yaml exec api alembic upgrade head
```

(Tip: `export COMPOSE_FILE=compose.dev.yaml` in your shell rc and drop
the `-f` from every compose invocation.)

## 3. Daily commands

All `up.py` / `down.py` commands take an optional `dev | stage`
positional; if omitted, they prompt (or default to `dev` under
`--non-interactive`).  This page assumes `dev`; for stage see
[STAGING.md](./STAGING.md).

| Command | What it does |
|---|---|
| `./scripts/up.py dev` | Configure (if needed) + start the stack.  Re-run after editing `.env.dev`. |
| `./scripts/up.py dev --reconfigure` | Re-run the wizard even if `.env.dev` is complete. |
| `./scripts/up.py dev --non-interactive` | CI mode — fail fast on any missing required env. |
| `./scripts/up.py dev --skip-build` | Don't auto-trigger `build.py` even if Dockerfiles changed. |
| `./scripts/down.py dev` | `docker compose down`.  Preserves all volumes + `.data/`. |
| `./scripts/down.py dev --clear` | `down -v` + wipe `.data/{workspaces,workspace-meta,projects}`. |
| `./scripts/down.py dev --nuclear` | `--clear` + remove built platform images (`polaris/{api,worker,web}:dev` + the workspace runtime trio). |
| `./scripts/build.py [--only X] [--force] [--push REGISTRY]` | Build / push the per-workspace runtime images.  Shared between dev and stage. |

For ad-hoc compose ops:

```bash
docker compose -f compose.dev.yaml logs api -f
docker compose -f compose.dev.yaml logs worker -f
docker compose -f compose.dev.yaml exec api alembic upgrade head
docker compose -f compose.dev.yaml ps
docker compose -f compose.dev.yaml restart web   # vite picks up vite.config.ts changes
```

Editing `apps/api/`, `apps/worker/`, `apps/web/`, or any of the
in-monorepo packages takes effect live — uvicorn `--reload` and Vite
HMR watch the bind-mounted source.  Image rebuilds are only needed
when a Dockerfile or its build context (system packages, lockfile)
changes.

## 4. TLS

Polaris doesn't ship a self-signed / `localhost` mode.  Traefik does
DNS-01 ACME against Cloudflare, so:

1. Pick a domain you own that's on Cloudflare DNS.
2. Set `POLARIS_DOMAIN` in `.env.dev`.
3. The wizard validates your `CF_API_TOKEN` (DNS-write scope) before
   bringing the stack up; Traefik then issues + renews wildcards
   automatically.
4. Open `https://${POLARIS_DOMAIN}/` (apex), `https://vnc.${POLARIS_DOMAIN}/`
   (dev VNC), `https://ide-<hash>.${POLARIS_DOMAIN}/` (per-workspace
   IDE), etc.

A separate cert pair covers `prod.${POLARIS_DOMAIN}` and
`*.prod.${POLARIS_DOMAIN}` for the publish plane, and a third covers
`*.s3.${POLARIS_DOMAIN}` for MinIO virtual-host bucket addressing.
Traefik manages all three from the same DNS-01 flow.

## 5. Tests

```bash
# One-time / after pyproject edits.  Materialises the shared .venv/ at the repo root.
uv sync --all-packages --all-extras

uv run --package polaris-api pytest apps/api/tests -v
uv run --package polaris-worker pytest apps/worker/tests -v
uv run --package polaris-design-intent pytest packages/design-intent/tests -v

# scripts/ has its own self-contained env (PEP 723 inline deps).
cd scripts && uv run --group dev pytest

# Frontend type-check + production build run inside the web container.
docker compose -f compose.dev.yaml run --rm web pnpm typecheck
docker compose -f compose.dev.yaml run --rm web pnpm --filter @polaris/web build
```

See [TESTING.md](./TESTING.md) for the full matrix (auth flows,
multi-agent flows, SSE assertions, publish smoke).

## 6. Common dev workflows

### 6.1 Reset everything

```bash
./scripts/down.py dev --clear         # interactive; drops all workspace state + platform pg/redis
./scripts/down.py dev --clear --force # non-interactive
```

Wipes per-workspace containers, per-project compose state, workspace
meta, the Postgres / Redis volumes, and the registry data.  Built
platform images survive; use `--nuclear` to drop those too.

### 6.2 Stop without losing state

```bash
./scripts/down.py dev             # docker compose down — keeps volumes + .data/*
```

`docker compose down` removes the stack containers but leaves every
named volume and the `.data/` tree intact.  The next `./scripts/up.py dev`
recreates the containers from the existing volumes.

### 6.3 Apply a new migration

```bash
docker compose -f compose.dev.yaml exec api \
    alembic revision --autogenerate -m "add foo"
docker compose -f compose.dev.yaml exec api alembic upgrade head
```

Worker reads via the same `polaris/api:dev` image's `apps/api` editable
install (re-registered against the bind-mount path on every container
start by `apps/worker/entrypoint.sh`), so no second install needed.

### 6.4 Rebuild workspace runtime images after CLI / template changes

```bash
./scripts/build.py --only workspace
# Per-session workspace containers keep the old image until next session;
# `./scripts/down.py dev --clear` wipes them so new sessions get the new image.
```

`./scripts/build.py --only workspace` triggers on changes to:
- `infra/workspace/Dockerfile`
- `infra/workspace/polaris-cli/*` (the workspace-side `polaris` CLI)
- `infra/publish-templates/*` (publish scaffolds COPY'd into
  `/opt/polaris-publish-templates`)

### 6.5 Logs

| What | Where |
|---|---|
| api / worker / web | `docker compose -f compose.dev.yaml logs <svc> -f` |
| Per-workspace container | `docker logs polaris-ws-<hash>` / `polaris-br-<hash>` |
| Traefik | `docker logs polaris-traefik-1` + `http://localhost:8090/dashboard/` |
| Publish SSE | The PublishPanel's live-log section, or `polaris publish` stdout inside the workspace |

### 6.6 Talking to the DB directly

```bash
docker compose -f compose.dev.yaml exec postgres psql -U root polaris
# or, from the host (Postgres is published on 127.0.0.1 with a dynamic port):
psql "postgresql://root:123456@127.0.0.1:$(docker compose -f compose.dev.yaml port postgres 5432 | cut -d: -f2)/polaris"
```

### 6.7 Headless server? Use the dev VNC

The `dev-vnc` service in `compose.dev.yaml` is a chromium container
pre-pointed at `https://${POLARIS_DOMAIN}/`.  Open
`https://vnc.${POLARIS_DOMAIN}/` from your laptop and click anywhere
in the chromium frame to grab control — full clipboard / camera APIs
work because the page is served over HTTPS via Traefik on the same
wildcard cert.  No auth on the route by default — **trusted networks
only**.  Set `SELKIES_PASSWORD` on the service to gate it.

## 7. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `./scripts/up.py dev` complains about Docker | Daemon not running or current user not in `docker` group | Start Docker; `sudo usermod -aG docker $USER && exec newgrp docker` |
| Traefik 502 on apex / vnc | api / web container still booting (uvicorn `--reload`, Vite cold start) | Wait ~10s; `docker compose -f compose.dev.yaml logs <svc>` |
| TLS cert errors on first up | Cloudflare DNS-01 hasn't completed yet | Watch `docker logs polaris-traefik-1`; first issue takes ~30–60s |
| `polaris/ide` build hangs ~5 min | Yarn workspaces + Theia compile on first build | Normal; subsequent builds use the cache |
| Session stays `queued` | Worker not running or crashed | `docker compose -f compose.dev.yaml logs worker -f`; restart with `docker compose -f compose.dev.yaml restart worker` |
| IDE iframe shows "waiting for agent" forever | Codex never called `set_project_root` | `docker logs polaris-ws-<hash>` for the Codex transcript; often a scaffold crash |
| Workspace container exits with auth error | `~/.codex/auth.json` missing on host | `codex login` on the host, then `./scripts/down.py dev --clear && ./scripts/up.py dev` |
